# 0.0.8 · 重做终端工作台

[文档中心](README.md) · [路线图](roadmap.md) · [0.0.7 基线](plan-0.0.7.md)

2026-11-23。0.0.7 验证了内核与真实终端的通信，但日常任务要在多层框和弹窗间往返。0.0.8 重做操作界面，把输入、观察进展、处理审批和检查交付物连到一个工作面上。

| 工作面 | 交付标准 |
| --- | --- |
| 视觉与布局 | 顶部显示会话与连接状态；宽屏提供可扫描的任务导航，窄屏优先显示选中任务并可切换队列。减少重复边框和提示。提供跟随终端、深色、浅色和无彩色模式。校验 120×32、80×24、48×18 以及极小窗口。 |
| 编辑与提交 | 持续可见的多行草稿，支持光标移动、中文与组合字符、中间插入和删除、长文换行、受限草稿大小。Windows 控制台粘贴可能产生普通回车，因此保留 `Ctrl+S` 显式提交；粘贴不会派发任务、命令或审批。 |
| 工作流 | 可搜索命令入口和一致的导航；任务细节直接显示提交内容、模型输出、计划、待办、失败原因和交付入口。无障碍依靠文字状态，不用颜色区分审批决策。切换会话、查看交付、恢复连接不应误提交或丢掉尚未确认的操作。 |
| 权限与恢复 | 审批仍绑定原任务和审批 ID，展示实际操作及参数。未知外部结果仍不重放。使用既有应用协议与 SQLite；不在终端增加权限旁路。 |
| 验收与发布 | 用 Ratatui 缓冲验证主题和尺寸，使用 Windows ConPTY 与 Debian PTY 跑真实 app-server 离线流程。记录可审阅的真实渲染，复验打包后的两个平台，核对 GitHub 标签、正式 Release 和资产校验值。 |

## 调研与取舍

- [Codex CLI TUI](https://github.com/openai/codex/tree/a1604a8c0554c09c1be45e5a121bb1889b4d9a50/codex-rs/tui)：核对 `chat_composer.rs` 的 Unicode 编辑与粘贴分流、命令调度以及 `approval_overlay` 的截断详情测试。采用固定的编辑区和明确的提交键；首版不做 Vim 模式和历史搜索复刻。
- [Claude Code 交互模式](https://code.claude.com/docs/en/interactive-mode)与[公开变更记录](https://github.com/anthropics/claude-code/blob/2771d5568ad888e44c7d988f616aa17dd44ced91/CHANGELOG.md)：采用可搜索的本机命令与高对比度主题。公开仓库用于核对行为和边界，不把它当作终端实现源码。
- [OpenCode TUI](https://github.com/anomalyco/opencode/tree/d284e7ce17d0a98c80d0bebd5cc6dce2dbdd5f74/packages/tui)：参考会话历史回补、终端尺寸以及审批显示测试。任务列表和长内容分别处理，窄屏给正文空间。
- Ratatui 继续作为终端渲染层。审查 0.0.7 的 `lru` 间接依赖告警与升级所需 Rust 版本并记录结果；依赖升级要通过双平台发布构建。

## 工作区与后续

参考仓库浅克隆至 `D:\Fliuno-References`，新构建使用 D 盘独立目标位置。发布前检查两盘空间，保留已发布包与验证环境。GUI、原生 macOS 沙箱、长期后台通知和跨会话工作收件箱不进入本版。后续版本按可以完整验收的用户工作流来切分；0.0.15 是授权上限，不为凑版本号发布小改动。
