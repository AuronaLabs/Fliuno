# 0.0.6 · 内核现代化

[文档中心](README.md) · [路线图](roadmap.md) · [上一版验收](plan-0.0.5.md) · [0.0.7 TUI](roadmap.md#007终端工作台)

调研日期：2026-11-22。以 Rust、SQLite 和现有本机协议为基础。0.0.6 用无界面客户端验收，Rust TUI 从 0.0.7 起步。

目标是一条可以由用户随时接管的工作流。用户选择项目资料与规则，提交任务并查看计划，在模型需要决策时补充信息，批准具体改动，再检查和修订交付物。客户端断线后可接回同一运行，从持久状态得知需要处理哪一步。

## 发布范围

| 顺序 | 交付 | 验收 |
| --- | --- | --- |
| 1 | 权限策略与授权管理 | 默认逐次审批。宿主可显式启用工作区内指定的本机只读能力。用户可对指定操作创建有期限的会话或工作区规则，查看、撤销并检查命中理由。规则作用域、工具注册摘要及操作约束联合匹配。 |
| 2 | 任务控制与待办 | 本机模型任务可保存可审阅的计划和澄清请求。运行时补充指令按任务修订号提交，在下一次模型派发前消费。客户端在现有工作台水位上读取待审批、待答、可恢复或需核对的动作。 |
| 3 | 上下文、项目资料与记忆 | 显式指定或排除记忆，按作用域复用项目说明。提交时冻结来源与修订号。给出实际使用、因预算省略和摘要替换的来源，以及字节估算、总 Token 计数及其覆盖范围。 |
| 4 | 对账与修订交付物 | 对已有远端核对入口补上持久结论和证据。交付物可引用上一稿，并保留各稿标识与摘要。用户可在无界面流程中比较文本、选择指定版本继续。 |
| 5 | 工具更新与运行连接 | 先让新旧配置分阶段生效，核对旧注册身份与撤销规则。通过独立宿主验证客户端重连、退出与服务重启的区别。把错误、恢复能力和待办原因整理成可由 TUI 消费的接口。 |

## 策略与执行语义

- `AllowOnce` 继续绑定原调用。跨任务适用的会话或工作区规则是独立的显式授权。授权记录绑定作用域、不可变的注册摘要和经过验证的操作约束，并设到期时间。第一版优先使用精确匹配，限制可为未来调用保存授权的工具集合。
- 策略先判断禁止项和隔离能力，再匹配规则。首批只读能力由本机宿主定义，限制在绑定工作区内。MCP 注解和模型描述属于输入数据。策略允许之后，仍通过同一持久调用身份、路径验证、派发和结果记录。
- 规则新增、撤销与执行准备由持久状态决定。撤销约束此后尚未派发的调用。重启后继续校验期限、当前策略和注册摘要。身份变化要求新授权。取消和未知结果保留原来的执行边界，已有未知调用不得通过规则自动重放。
- 工具版本更新先从可验证的注册发布开始。新任务绑定新版本，旧任务只有在原版本仍可用且授权有效时才使用旧绑定。撤销或不可用须给出结构化处理原因。热重载须有跨重启的语义后再开放。

## 交互和结果

- 计划、澄清和操作审批分别保存。对模型任务先建立可重复读取的澄清请求与一次性答复，复用待输入和事件水位机制。补充指令交给当前任务的下一次安全模型边界。协议区分已接收、已使用、未使用，并拒绝过期修订号。
- `work/subscribe` 已提供同一读取点的快照和事件水位。扩充待办投影时沿用这个水位，并限定返回数量。服务端执行操作时复查条件，防止客户端根据旧快照恢复或批准。
- `task/checkRemote` 已保存远端观察。核对结论另存原调用身份、来源、证据摘要和操作者，供工作台并列展示本地结束状态与外部结论。外部结论的变更不会触发工具派发。缺少证据时保留未核对状态。
- 复用不可变 Artifact、摘要和任务输入引用。先用文本报告验证草稿、审核反馈和修订之间的关联。被标记为可应用的工作区改动须重新校验文件基线，并走已绑定的执行审批。通用外部操作回滚另行设计。

## 上下文与评测

- 让用户指定记忆、关闭注入或选择项目资料。工具输出和外部文档保持数据身份，项目说明由宿主显式选入。任务保留选中的 ID、修订和来源，支持查看为何选中或省略。显式选择因预算失败时报告可调整项。
- 保留已有词法和语义融合，按模型配置评测阈值。时间衰减先用于可验证的软信号，显式修订、删除与过期优先。评测增加中英改写、互相冲突的新旧事实、无答案、短词及不同工作区。记录命中、误注入与任务创建延迟。
- 展示供应商给出的总 Token 数和覆盖范围，以及按来源分组的本机估算。压缩前后的来源及省略理由随任务保存。只有在计数器确实支持归因时才输出逐项 Token 数。

## 发布验收

1. 旧配置继续要求审批。启用后能在限定范围内完成只读任务，写操作仍待审批。验证撤销、过期、重启、参数和工具版本变化以及不同工作区。用真实执行入口断言工具调用次数。
2. 跑通提交 → 只读收集 → 澄清或补充指令 → 审阅写入 → 断线续读 → 查看修订稿。覆盖重复提交、旧修订号、答复与取消竞争、客户端退出和服务重启。
3. 制造远端已收到但本地失去响应的任务，在客户端完成一次核对，验证原事件保留且调用没有重发。检查同一工作台视图上的恢复、预算和对账提示。
4. 运行协议契约兼容测试、Windows 无界面流程和可用 Linux 验收，记录计数、延迟和原生隔离的实际覆盖。新增接口由 `initialize.capabilities` 公布，数据库变更随迁移和版本说明交付。

TUI 从 0.0.7 起复用这些接口。GUI、原生 macOS 沙箱、并行任务高级编排、通用回滚和实验性协议扩展另行排期。

## 调研依据

- ChatGPT Work 的工作流程包括跟进、回答问题、改变方向和批准操作。Codex App Server 公开区分活跃回合追加输入、计划与变更事件、指令来源。采用可持久化的客户端契约，先在本机模型任务验收。 [Get started with ChatGPT Work](https://learn.chatgpt.com/docs/get-started-with-work) · [Codex App Server](https://learn.chatgpt.com/docs/app-server)
- ChatGPT Work 支持预览产物并提供修订反馈。Claude Cowork 更强调任务内指引以及项目资料、说明和记忆。先做可指认且可重现的来源与交付版本。 [Work with files](https://learn.chatgpt.com/docs/artifacts-viewer) · [Cowork 入门](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork) · [Cowork Projects](https://support.claude.com/en/articles/14116274-organize-your-tasks-with-projects-in-claude-cowork)
- Codex 分开配置审批与隔离。OpenCode V2 提供持久项目规则和一次批准。Claude Code 的拒绝规则优先于允许规则，文件回退也有跟踪边界。Fliuno 首版规则采用更窄的能力和作用域。 [Codex 审批和隔离](https://learn.chatgpt.com/docs/agent-approvals-security) · [OpenCode Permissions](https://opencode.ai/docs/permissions/) · [Claude Code Permissions](https://code.claude.com/docs/en/permissions) · [Claude Code Checkpointing](https://code.claude.com/docs/en/checkpointing) · [MCP 工具注解](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)
- Temporal 解释了外部副作用与本地完成记录之间的失败窗口。LangGraph 的持久中断也依赖明确的恢复边界。Fliuno 沿用现有调用身份和事件，分别保存暂停、使用答复与对账结果。 [Temporal Activity Definition](https://docs.temporal.io/activity-definition) · [LangGraph Interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)
- LongMemEval 把记忆更新、时间推理和无答案分开评测。0.0.5 的 E5 独立小样本命中 6/7，12 个问题无误注入，p95 为 21.75 ms。后续保留这组基线，用新的独立样本衡量版本收益。 [LongMemEval](https://arxiv.org/abs/2410.10813) · [Fliuno 中英检索评测](memory.md#中英检索评测)
