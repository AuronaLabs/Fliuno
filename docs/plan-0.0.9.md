# 0.0.9 · 工作区工作中心

[开发路线图](roadmap.md) · [上一版设计](plan-0.0.8.md) · [终端工作台指南](workbench.md)

日期：2026-11-27。0.0.8 已把单个会话的任务、审批、草稿与交付物放进一个工作面，但多个会话仍要靠手动切换才能发现待处理事项。内核已经提供工作区范围的工作快照、待审批收件箱、任务摘要、下一步动作和历史搜索；0.0.9 要把这些能力整合成 TUI 中可直接操作的工作区中心。

## 调研与取舍

Codex CLI 提供恢复最近或指定会话、会话分支和输入队列等操作；Claude Code 支持恢复会话、运行中排队输入及会话内待办；OpenCode TUI 提供会话切换、分支、队列管理和历史搜索。共同趋势是长任务不能只靠当前屏幕：用户需要恢复上下文、安排后续输入并跨会话查看进展。

Fliuno 本版优先解决工作区层面的可见性和重新进入上下文：把审批、澄清、恢复/对账建议、运行中及近期任务集中展示；允许按字面内容跨会话搜索已完成历史，并跳回匹配任务。提示排队和多窗口会改变任务执行语义，留待有明确持久化与取消行为设计后再做，不把临时 UI 缓存伪装成可靠队列。

## 范围

| 工作流 | 交付内容 | 验收条件 |
| --- | --- | --- |
| 工作区收件箱 | 在当前工作区汇总最近 50 项任务、最多 100 个待审批项、状态计数与内核推导的待处理动作；提供“需处理 / 运行中 / 最近”筛选。 | 使用两个以上会话覆盖审批、澄清、运行、失败/中断与已完成状态；行内以文字呈现状态和动作，不依赖颜色。 |
| 上下文跳转 | 从收件箱进入原会话和具体任务；保留离开前的草稿和附件；跨会话跳转不自动审批、取消、恢复或重发任务。 | 进程验收核对目标 workspace/session/task ID；离线、过期项和任务更新后仍安全失败或刷新。 |
| 历史查找 | 按用户输入的字面词语跨当前工作区搜索已完成历史，展示匹配任务摘要；使用固定 `throughSequence` 和返回游标分页，清楚报告有界扫描跳过的大型记录。 | 覆盖中英文、用户/助手角色筛选、无结果、重复分页和并发新任务；不会把新记录混入已开始的分页结果。 |
| 实时更新 | 收件箱开启时订阅工作区范围的工作快照；快照水位推进后更新列表，关闭时回到当前会话订阅。 | 多会话事件推进一致的水位；重连后不会丢失较新状态或重复执行客户端操作。 |
| 终端体验 | 加入可搜索命令入口；在 120×32、80×24、48×18 与窄屏阅读队列、空状态、加载状态和错误状态。 | Ratatui 缓冲测试与 Windows ConPTY、Debian PTY 真实进程验收一致。 |

## 技术边界

- 继续使用应用协议 `0.1` 和现有 SQLite schema 74；本版不需要数据库迁移或新的权限旁路。
- 用 `work/subscribe` 的工作区作用域和 `workspace/searchHistory` 已有快照游标；所有请求继续服从协议的分页、扫描与响应字节上限。
- UI 动作最终仍由现有任务、审批和恢复 RPC 校验；状态未知时不自动重放。
- 只收件箱打开时做工作区级刷新；在普通会话视图时维持现有订阅负载。

## 不在本版

- 持久提示队列、自动开始排队任务及其重启/取消语义。
- 跨多个 workspace 的总览、多 TUI 窗口协作、后台通知与 GUI。
- macOS 原生隔离、语义记忆重构与新的外部 Agent 协议适配。

## 完成门槛

工作区范围的视图能发现并安全处理其他会话里的待办，能从历史搜索回到匹配任务；草稿和附件在跳转期间保留；跨会话 RPC 均在 workspace 边界内；Windows 与 Debian Linux 的真实 TUI 流程通过。达到完整交付后再评估是否发布 0.0.9；不为版本号拆分小更新。
