# 启动配置读取

`fliuno-app-server` 的 MCP、ACP、A2A、exec 和 terminal JSON 配置由宿主通过命令行指定，运行中不接受模型或 RPC 改写。这五类文件统一经过独立的 `configuration` 模块：

- 每份最多 1 MiB，实际读取最多 1 MiB + 1 字节探测超额；不先整文件分配再检查 metadata。文件在读取中增长也不会越过该字节预算。
- 路径必须指向普通文件，打开前检查并在打开后复核句柄；正常指向普通文件的符号链接可以使用。该接口面向受信宿主路径，不承诺抵御任意并发文件系统替换，也没有单独的磁盘 IO deadline。
- 在打开任务数据库、启动配置中的进程或连接配置中的 MCP 服务前，先读取并反序列化全部五类文件。后面文件的 JSON 错误不会使前面的 MCP 注册先产生连接。
- JSON 错误只输出配置种类和行列位置，文件错误只输出配置种类及固定诊断，不回显配置值、未知字段或文件路径。语义、权限、资源预算和可用凭据继续由对应适配器检查。

这项预检保证读取和 JSON 契约失败发生在注册前，不把各适配器的全部语义校验变成跨模块事务。例如一个通过反序列化但端点不合法的 A2A 配置仍由 A2A 适配器拒绝；更早完成的 MCP 注册此时可能已经初始化，随后随启动失败回收。

每份 JSON 的预算与应用协议帧预算分别定义；二者均为 1 MiB，但承担不同边界。多个配置解析后的对象与 serde 开销不由文件字节上限精确限定 RSS。Skills 的目录读取有自己的能力目录和文件预算，不使用这套 JSON 加载器。

测试包括持续增长的 reader、恰好 1 MiB 的合法 JSON、解析/读取错误脱敏、所有五种 CLI 参数的超额拒绝、普通文件检查，以及后续 ACP JSON 错误时本机 MCP fixture 收不到请求、任务数据库未创建。
