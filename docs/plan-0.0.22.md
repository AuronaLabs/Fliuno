# 0.0.22：项目指南、检查和日常工作台

[路线图](roadmap.md) · [0.0.21 使用指南](workbench.md) · [发布基线](execution-evidence.md#0021-安装包验收)

目标：在已有项目中打开 Fliuno，能看到它参考了哪些指南、可以跑哪些项目检查，以及本轮改动是否通过。已有会话、模型配置和审批边界继续适用。本计划先以 v0.0.21 作对照；版本号只在准备候选时更新。

## 调研和实际缺口

- [Codex 项目指令](https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide#using-agentsmd) 与本地 Codex `a1604a8` 的 `codex-rs/core/src/agents_md.rs` 对照：使用有大小上限的目录指南，并保留来源。Fliuno 当前的共享提示建议模型主动寻找指南；模型可能跳过，现有指令修订只能追踪客户端显式设置的会话指令。
- [Claude Code 项目记忆与规则](https://code.claude.com/docs/en/memory) 区分项目规则与自动记忆，可检查加载的文件；本地 Claude Code `2771d55` 的 `CLAUDE.md` 提供实际项目指南的例子。[OpenCode Instructions](https://opencode.ai/docs/instructions) 和本地 `d284e7c` 的 `packages/core/src/instruction-discovery.ts` 区分初始项目规则与后续按访问发现的嵌套规则。Fliuno 先做显式选择项目根目录的指南，再验收按路径发现，避免遍历用户目录或误读无关规则。
- [OpenCode 权限](https://opencode.ai/docs/permissions/) 区分动作和资源；本地 Codex `a1604a8` 的 `codex-rs/tui/src/slash_command.rs` 把项目操作放进可查找的命令入口。Fliuno 已经按配置注册项目检查，但用户要等审批才看到真正可以运行什么。发现检查和批准检查可以分开。
- [Ratatui 布局](https://ratatui.rs/recipes/layout/) 支持让对话和弹层共用布局约束；v0.0.21 的 80 列 Windows 实际终端中，精确编辑主预览的绝对路径和 64 位摘要各占两行。48 列要滚更多行。现有参数页保留完整绑定信息，主预览可以优先显示目标、改动和后果。

## 开发板块

1. **项目指南与来源**。先支持对当前工作区根目录一份 `AGENTS.md` 做显式启用、预览和停用，后续评估 `CLAUDE.md` 回退和目标目录内的发现。用户同意后才发送正文给模型。借用内核的有界快照和归因，冻结每轮使用的路径和内容摘要；文件变更提示重新预览，已开始的任务继续使用原快照。项目文件的内容不提高工具权限，不改模型端点、不触发命令，不加载链接、外部导入或用户主目录中的文件。旧会话无项目指南时保持原行为。
2. **项目检查的可见性**。从真实宿主注册而来，提供当前项目可用检查的只读摘要，列出名称、固定输入和缺失原因；不要在列表里暴露环境或凭据。没有配置时给出一条可操作的指引。执行仍须使用原工具注册、哈希和审批；不能把从项目指南读到的命令当作检查注册。
3. **工作台和首次使用**。拆出可共用的审阅组件，先把精确替换页的长技术字段整理到详情，保持预览和审批操作在同一屏。审阅快捷键、图文排布和默认焦点在 48、80、110 列比较，覆盖中英文、深浅配色和低高度。优先补齐首次配置里直接影响完成连接的简体中文。把命令发现途径和模型配置写进用户指南。
4. **发布和文档**。按板块提交并推进测试。更新 README、文档中心、工作台指南、协议和 CHANGELOG；发布前从同一候选提交取两平台原生包、便携包和摘要。升级基线为 v0.0.21。开发、截图和安装证据放 D 盘，复用构建目录并检查 D/E 余量。

## 开发验证

Windows ConPTY 已通过精确替换的 48、80、110 列预览：可同屏看到相对路径、原文、替换文本和审批操作。48 列切到详情仍可查看完整工作区路径和基准摘要，切回预览不会执行写入。Linux 与其他主题留待本版候选验证。

Windows 的完整工作台套件已通过 30 项 ConPTY 测试。项目指南在 48、80、110 列可审阅；48 列覆盖文件改动阻止发送、保留草稿、重新审阅及重开后续用。四种模型协议另用回环 HTTP 检查指南进入用户上下文。见[开发证据](execution-evidence.md#0022-项目指南开发验收)。

## 验收门槛

- 离线请求检查指南仅在用户启用的工作区生效，记录来源和上限；跨工作区、撤销、路径边界、内容变更及断线重开都不扩大范围。四种协议保留相同的上下文权重，普通对话与现有旧会话可用。
- Windows 与 Debian 的临时项目在真实终端里从指南预览走到代码修改、隔离检查和最终回执。核对内核快照、实际磁盘 diff、退出状态和历史。未配置检查、项目规则与授权冲突、操作被拒绝都要走一遍。至少做一次真实模型试跑并单独记录边界。
- 两平台完整 CI、安装/升级/卸载及重装、安装后的 PTY 场景和 SHA-256 均通过。保留跨宽度截图；源码、实测结果和发布资产对应的提交可追踪。完成一个板块时不单独发版。
