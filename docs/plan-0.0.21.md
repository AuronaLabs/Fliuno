# 0.0.21：从对话到项目 Agent

[开发路线图](roadmap.md) · [现有工作台](workbench.md) · [工程验收](execution-evidence.md)

目标：从真实工作目录启动 Fliuno，交给它一项小型代码修改。它能自行定位相关代码和项目指南，提出可审阅的小改动，运行项目允许的检查，最后给出具体文件和检查结果。普通对话仍在原处完成，任务机制服务于这条流程。

## 调研与当前缺口

- [Claude 提示工程](https://platform.claude.com/docs/zh-CN/build-with-claude/prompt-engineering/overview) 与 [OpenAI 提示工程](https://help.openai.com/zh-hans-cn/articles/10032626-prompt-engineering-best-practices-for-chatgpt)：把行为与成功标准写具体，用可测的场景迭代。四个 Fliuno 适配器目前各自使用一句泛用工作提示，没有区分对话、文件和项目改动。
- [Claude 工具定义](https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools) 与 [OpenAI Function Calling](https://developers.openai.com/api/docs/guides/function-calling)：工具描述需交代何时使用、输入和返回值；模型收到可辨认的执行结果后才能继续。当前工作区搜索最多查看八个已明确命名的文件；命令工具需要额外执行配置；部分确定未执行的错误会直接结束任务。
- 本地 Codex `a1604a8` 的 `codex-rs/models-manager/prompt.md` 显式说明如何读项目指南、修改和逐步验证；本地 OpenCode `d284e7c` 的 `packages/core/src/session/runner/prompt/system.txt` 与 `packages/core/src/tool/plugin/edit.ts` 把仓库工作方式和工具契约分别维护，编辑失败时给下一步线索。Claude Code 本地 `2771d55` README 将代码库理解和终端工作列为核心能力；其 [设置文档](https://code.claude.com/docs/en/settings) 补充用户和项目的配置边界。
- [OpenCode 供应商](https://opencode.ai/docs/providers/) 和 [权限](https://opencode.ai/docs/permissions/) 分开管理连接、模型以及按动作和资源授权。Fliuno 已有多个模型档案、端点/密钥设置和权限规则，但缺少独立供应商身份；审批常以工具名和原始参数开头，容易把托管产物误认成写文件。

## 开发顺序

1. **共享提示词与工具闭环**：在 Rust 内核维护有版本的行为契约，四种协议复用；只使用实际注册的工具。普通写作直接在对话中交付；用户要求可下载文档时可生成托管产物；要求写项目文件时使用工作区工具。交付回执来自持久化结果，分别显示可打开、可导出或已保存到哪个路径。审批说明操作、对象、影响和拒绝的结果，详细参数另行查看。明确区分失败、拒绝、验证未运行和结果未知。
2. **真实项目工作流**：添加受工作区边界约束的文件发现和内容搜索，结合现有读取、哈希、补丁和写入；项目指南作为低于用户决定的上下文，不能改变权限。接通可发现、可审阅且经过沙箱的项目检查。检查前显示工作目录和实际命令；允许小范围、可撤销的只读授权；改动、命令与外部副作用遵循内核策略和 authority 绑定。能让模型处理已知错误并修正输入；结果未知不得自动重放。把工具进度、文件改动与检查结果放回对话主线。
3. **供应商、协议和历史身份**：供应商是命名的 Base URL 与凭据引用，支持默认预设和自定义；档案绑定供应商、独立协议 ID、模型与思考强度。首批 ID 为 `openai.compatible`、`openai.responses`、`claude.message`、`google.gemini.interactions`。保留旧配置读取，升级测试覆盖本地无密钥连接、凭据与默认档案。回复持久化发出调用时的 `供应商标识/模型ID`；旧记录缺少身份时如实显示，切换活动模型不重标旧回复。
4. **终端体验**：设置独立入口，跟踪中文和英文完整度。语言切换即时可见、重启保留；模型回复语言随用户意图，不取决于界面语言。重做 F1 的命令搜索和快捷键，统一圆角、对比度和焦点。项目工作区、操作审批和交付的关键内容在窄屏保持可读。

## 多步骤项目的进度

本地 Codex `a1604a8` 的提示词要求多阶段工作报告可核对的步骤，简单问题直接答复。Fliuno 复用已有的 `task_publish_plan` 和 `task/getPlan`：在主视图显示已完成数量和正在处理的步骤，完整清单可在详情中查看。计划由模型报告，和内核验证过的写入、退出码分开展示。发布计划既不批准文件写入也不启动项目检查。真实终端用例要核对计划更新能在下一次审批前看到，且普通写作不出现计划。

## 从对话进入项目工作

本地 Codex `a1604a8` 的 `codex-rs/tui/src/slash_command.rs` 提供 `/diff` 和 `/review`；[Claude Code 交互参考](https://code.claude.com/docs/en/interactive-mode) 将计划、权限和改动审阅作为会话中的操作；[OpenCode TUI](https://opencode.ai/docs/tui/) 用命令面板发现操作。Fliuno 保留对话作为提需求的入口，把项目名称、工作区路径、待审操作和可核对的结果放在主视图。

- 增加 `/changes`（也可在 F1 中搜索）。从内核已记录的工具结果查看当前任务实际写入的相对路径、已应用的补丁、检查命令、退出状态及保留的输出。它是本轮的执行记录；项目里的其他改动不计入，也不会被覆盖或重置。
- 首屏提示从定位代码、修改和验证入手。普通问答保持简洁；只有写入或运行项目检查后才显示审阅入口。保留旧会话数据，单独标记用测试替身验证的工具流程与真实模型评估。
- 真 PTY 验证在审批前不显示已应用的补丁，运行后补丁和磁盘真实 diff 一致，检查输出可打开；在 48、80、110 列逐一查看布局。

## 已验证的首批改动

- 四种模型适配器发送同一份项目 Agent 提示词，Gemini 的 Token 预检也计入同一份指令。离线 HTTP 用例检查请求与工具结果，真实模型的行为评估另做。
- `workspace_find` 支持未知路径的字面文件名和源码搜索。它不会跟随链接，默认略过隐藏、生成目录；在文件、目录、结果上限达到时报告扫描情况，返回工作区内路径和行号。内核用例靠实际搜索、读取哈希和补丁写入更新一份 UTF-8 文件，再读回验证。
- 审批期间发现文件变化时，旧写入不会执行。模型收到 `workspace_base_changed` 后可以重读、重新提出补丁；测试核对用户期间追加的内容留在文件中，两次补丁需要不同的审批。结果未知仍走中断和对账流程。
- Windows ConPTY + 本地模拟模型 API + 真实 app-server 通过中文短文直接回复、项目定位、补丁审阅、文件写入和回执流程。补丁与回执在 48、80、110 列留有截图；另一条 PTY 用例验证托管交付物的保存、预览、导出和拒绝。后续 Windows ConPTY 用例在临时 Git 仓库里完成补丁、重读和沙箱检查，核对实际 Git diff、退出码与隔离目录输出，保留 48、80、110 列审批和回执截图。另有原生执行用例覆盖非零退出、输入哈希变化、越界配置及私有写入。Linux 结果以对应 CI 记录为准。

`artifact_create` 的工具描述参与权限摘要。升级前待处理的旧审批如果与新注册摘要不符，需要重新提交；不能沿用旧审批执行。发布前会用 v0.0.20 存量数据核对这一路径。

## 项目检查：执行边界

本地 Codex `a1604a8` 的 `codex-rs/core/src/tools/approvals.rs` 区分命令范围、审批和沙箱执行；OpenCode `d284e7c` 的 `services/site/src/docs/content/permissions.mdx` 将权限与具体命令或资源匹配。[Claude Code 权限](https://code.claude.com/docs/en/permissions)、[Windows AppContainer](https://learn.microsoft.com/en-us/windows/win32/secauthz/appcontainer-isolation) 与 [Linux Landlock](https://docs.kernel.org/userspace-api/landlock.html) 用于核对约束。Fliuno 现有隔离进程从私有目录启动，不能直接检查刚改过的工作区；所以这阶段先给隔离执行增加项目输入快照。

- `integrations.execution` 的用户侧执行配置可以登记项目检查。程序、参数、输入文件清单由配置固定；模型仅提供每个输入的最新哈希。审批展示程序、参数、隔离方式以及会交给程序的文件。无隐式仓库挂载、无回退至可信宿主进程。
- 审批后读取文件，拒绝链接、路径冲突、超量和哈希不符，再放入私有执行目录。结果包含实际输入版本、退出码和输出；非零退出为检查未通过，超时与结果未知保留原有语义。未经用户配置的程序不会因某个项目文件的指令而获得执行权。
- 先用 Windows AppContainer 与 Linux Landlock 的可重复验收，证明检查读到 Agent 修改后的内容、运行前后真实工作区没有被检查程序改写，并验证旧哈希不会触发启动。随后增加可在设置中管理的检查项以及构建工具链所需依赖的接入；固定清单的快照不宣称能装载任意项目依赖树。

## 真实模型编码验收

[Claude Code 的实践建议](https://code.claude.com/docs/en/best-practices) 把测试和可验证结果作为完成任务的标准；本地 Codex `a1604a8` 的 `codex-rs/core/gpt-5.2-codex_prompt.md` 同样要求说明验证及未验证事项。Fliuno 新增一项独立于模拟模型 CI 的验收：使用明确选定的真实模型和临时 Git 项目，以固定的 Node 测试运行「首次失败 → 只改实现 → 重跑成功」。

验收对照真实 Git diff 和两次检查的内核记录。测试由宿主固定摘要并暂存，模型不能编辑测试或改检查参数；只允许验收目录内预期的读取、目标文件修改和选定检查，轮次有上限。模型的成功措辞不计为通过。第一次实测不增大默认轮次，以识别现有工具和预算的实际瓶颈。

可执行验收：`python examples/live_project_repair.py --config <仅模型的配置> --app-server <构建产物> --node <Node 可执行文件> --scratch <空闲的临时目录> --evidence <尚不存在的 JSON 文件> --steps 16`。该命令会使用真实模型调用，CI 默认不运行。

2026 年 11 月 28 日的 Windows 开发构建使用 `gpt-6.2-sol` 完成一轮验收：8 次模型尝试，固定检查退出码由 1 变为 0，比对 Git diff 只修改 `src/order-total.cjs`，最终答复报告了实际路径与 4 条通过的断言。记录同时保留先前失败：有一轮修改和检查都成功，但旧 8 次预算截断最终答复；另一次因模型提交无效 diff 而失败。开发版保留默认 8 次，同时支持显式 1 到 32 次；可纠正的 diff 格式错误现在有独立审计记录，模型可重提，旧提案不会写入。这个结果覆盖一个小型回归用例，安装包和 Linux 真实模型验收尚未完成。

一次真实修复中，模型用三份补丁才完成一行替换。下一步参考 [OpenCode 工具文档](https://opencode.ai/docs/tools/) 和本地 OpenCode `d284e7c` 的 `packages/core/src/tool/plugin/edit.ts`：给小改动增加基于原文的编辑，比手写 diff 行范围更直接。Fliuno 采用严格字节匹配，要求原文在目标文件中只出现一次，并继续绑定读取时的 SHA-256 和审批；不做模糊匹配、隐式批量替换或自动改行尾。TUI 审批和回执都展示原文与替换内容，测试覆盖找不到原文、原文有歧义和审批后文件被修改。保留 unified diff 用于多个位置的修改。 接入后使用同一真实模型再次完成回归，8 次模型尝试，精确替换一次、无需修订提案，固定检查退出码仍为 1 → 0。

## 供应商设置：从配置文件到工作台

[OpenCode 的供应商文档](https://opencode.ai/docs/providers/) 将连接与模型选择分开；本地参考 `d284e7c` 的 `packages/schema/src/config/provider.ts` 与 `packages/tui/src/component/dialog-model.tsx` 分别定义供应商配置和按供应商浏览模型的界面。调研时，Fliuno 已能读取 `[providers]` 并为回复保留模型身份，但旧编辑表单只能改内联连接，命名供应商要手工配置。开发版已用 `/settings` 管理连接和绑定，`/model` 继续管理当前和默认档案。

- 配置层提供独立的供应商写入和模型绑定操作。用户确认的配置版本必须匹配；写入前验证所有受影响的绑定，保留无关字段和旧档案。端点变更必须重新选择凭据；同一端点可轮换或保留凭据。无密钥连接仍限于本机兼容协议。
- 设置页分开列出供应商和模型档案。先建立连接，再绑定协议和模型；旧的单模型配置可以继续工作，也可由用户显式换绑。旧回复保持当时记录的身份。连接变更后需用新连接重新激活模型；已经就绪的运行应按现有运行边界处理。
- 验收用同一供应商绑定两个模型，再绑定本机无密钥供应商。核对并发修改、凭据变更、失败回滚、协议不兼容和重开后的显示；另以 48、80、110 列 PTY 核对编辑页和选择页。

已在 Windows ConPTY 用两家模拟供应商验证：共享有 Key 连接、独立无 Key 连接、保存冲突、显式应用后发给选中模型的请求、重启后历史模型标签。核对了 48、80、110 列的设置窗口。绑定页已接入目录；中文界面仍在开发。本机回放不等于候选包验证。详见[工程记录](execution-evidence.md#0021-项目-agent-开发验收)。

### 绑定时浏览模型目录

[OpenCode 的模型选择设计](https://opencode.ai/docs/models/)和本地 `d284e7c` 的 `packages/tui/src/component/dialog-model.tsx` 都把供应商和模型 ID 配对。Fliuno 在已有的绑定表单里复用目录选择组件，填入 ID 后继续核对思考强度和保存摘要，保持保存、启用和启动默认值各自独立。

- 本地客户端仅发送供应商 ID、配置修订、对话协议和可选分页游标。内核从同一配置快照读取地址和凭据，检查修订后才发请求；查询不需要先创建模型档案，也不接收客户端提供的地址或密钥。沿用现有适配器：[OpenAI](https://developers.openai.com/api/reference/resources/models/methods/list) 兼容目录使用单页查询，[Anthropic](https://platform.claude.com/docs/en/api/typescript/models/list) 和 [Gemini](https://aistudio.google.com/api-reference/models/list-models) 使用各自的游标。
- 用户按键发起查询，可按 ID 或显示名称筛选已加载项，显式翻页，选择后填回准确的模型 ID。返回表单时保留原输入；空目录、权限不足或不提供目录的网关都可手填。仅在服务声明能力时显示目录快捷键。
- 用环回服务验证两个供应商各自使用正确的地址、协议与凭据，分页不会串线，凭据回显不会进入目录。过期修订拒绝查询，不建立网络连接。Windows/Linux 都测试 RPC；终端走一次从查目录到保存并应用的完整流程，并检查窄屏提示与手填回退。

## 验收与发布门槛

- 用四种协议的离线回放检查实际请求与工具结果回流。中文短文在对话完成，零工具、零审批；托管产物可打开与另存且不冒充工作区文件；工作区写入此前可审阅，拒绝不修改文件，成功显示通过真实结果验证的路径。
- Windows 和 Debian 12 的临时 Git 仓库运行同一用例：中文请求定位未知文件，读取规则和测试，用小补丁改动，实现一次失败纠正并跑定向检查；比对实际 diff、退出码和最终报告。用离线协议回放验证内核行为，再单独记录真实模型试跑结果；不得把离线回放当作模型质量证据。额外覆盖取消、拒绝、边界路径、重复请求、未知结果和重开恢复。
- v0.0.20 数据升级后同时连两个供应商。切换协议、模型和默认档案，验证重开后历史标签正确，检查请求、日志和界面未泄露凭据。
- 真实 PTY 在 48、80、110 列检查中英文设置、F1、审批、进度和回执，保留截图。分功能提交，单一候选 SHA 通过 Windows/Linux 内核 CI、Windows x64 MSI 和 Debian 12 amd64 安装、升级、启动、项目用例与卸载；校验安装包和发布文件。按需复用 D 盘构建缓存并检查 D/E 空间。原生 macOS 和 GUI 另行排期。
