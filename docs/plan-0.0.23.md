# 0.0.23：发送前看得见，小窗口做得动

[路线图](roadmap.md) · [工作台指南](workbench.md) · [0.0.22 基线](execution-evidence.md#0022-安装包验收)

目标：在同一个项目里，用户能在发送前看懂本轮会带哪些材料；预算不够时知道哪里超限，并能保留草稿继续。小窗口模型应能在明确选定工具范围后完成项目工作的一部分。

## 调研与基线

- [Codex 的终端命令](https://developers.openai.com/codex/cli/slash-commands)将 `/status` 的用量与 `/compact` 的摘要操作分开。本地 Codex `a1604a8` 的 `codex-rs/tui/src/slash_command.rs` 有相同分工。Fliuno 已有草稿的历史预览和已运行任务的归因，可以接到同一个易找的入口，但两个报告要区分「下一次」和「上一次」。
- [Claude Code 的 `/context`](https://code.claude.com/docs/en/commands)显示主要来源和优化建议。本地 `2771d55` 的 `CHANGELOG.md` 记录过首条回复前工具低估、窄屏截断及切换模型后统计错配。Fliuno 先展示确知的预算来源和可比的字节估算；不知道 Token 数就明说，不能从各项字节画出精确 Token 百分比。
- [Anthropic 工具上下文](https://platform.claude.com/docs/en/agents-and-tools/tool-use/manage-tool-context)将工具定义延后加载，用更多模型轮次换较小的基础输入。Fliuno 有四种接口形态，先评估跨协议可复现的、用户显式选择的工具范围，不照搬某个供应商的专用行为。
- [OpenCode 的压缩配置](https://opencode.ai/docs/config/#compaction)区分输入预算、预留和近期保留量。本地 OpenCode `d284e7c` 的 `packages/tui/src/feature-plugins/sidebar/context.tsx` 只在有窗口时显示比例；`packages/core/src/session/compaction.ts` 另处理历史增长与压缩。Fliuno 已能缩减历史；空会话亦可超预算，不能把问题都交给历史摘要。
- 现有实测：相同回环模型用 8,192 的 Fliuno 配置上限时，带工具的短项目问答在发送前被拒；配到 32,768 后返回正确的指南信息。这不等于模型确实用了 8,192 个 Token。先保存 0.0.22 的实际请求字节与拒绝来源，再测新版本，区分本地估算、供应商计数及实际回复用量。

### 可复现的 0.0.22 结果

```powershell
python -B scripts/measure_draft_context.py ./fliuno-app-server.exe --version 0.0.22
```

输入 59 UTF-8 字节，已审阅的指南 72 字节，空历史、无记忆，工作台交互工具开启。用 SHA-256 校验过的 Windows 便携版在回环 `openai.compatible` 模拟服务测得：

| 配置窗口 | 结果 | 记录 |
| --- | --- | --- |
| 8,192 | 生成未发出 | 本地字节上限 8,064；序列化停止时下界 8,160；HTTP 请求 0 次。 |
| 32,768 | 回环问答完成 | 19 个工具；生成 JSON 12,397 字节；工具定义的规范化片段合计 7,630 字节。 |

两个计数分属请求正文和中性工具片段，不能等同于 Token。回环回复是固定值，只证明请求形状和调度边界。真实模型单独见[0.0.22 验收](execution-evidence.md#0022-项目指南开发验收)。

## 开发顺序

1. **诊断从内核开始。** 用固定工作区、模型档案和草稿留下一份 0.0.22 可复查基线。梳理工作台预览、供应商序列化和任务归因的共同字段。为发送前的本机检查提供有界报告：当前模型及预算、将使用的历史/指南/记忆、草稿体积和工具定义。预览不发送模型请求，不创建任务，不做网络 Embedding；因此部分来源可能只是估算，实际值随提交时的快照而定。
2. **减少固定开销。** 实测系统提示与工具描述、Schema 和可选工具的固定开销。在不改默认行为的前提下，用明确的工作范围验证缩减方案（例如内置项目能力与宿主登记的检查可以留下，额外集成需要显式选用）。确认工具定义、任务绑定、恢复和实际可执行范围一致；旧任务不会因新设置改变工具绑定，被移除或撤销的工具不会变成可执行。旧审批的权威摘要或结果未知状态不能被宽松处理。
3. **把预算提示接回对话。** 让 `/context` 可从输入框和 F1 打开。先放可执行的建议，再放细目；把上一轮失败和当前草稿分清。可直接调整已经有的历史、记忆和指南选择；更改后的草稿由用户决定何时发送。不自动重放已发生操作的任务。48 列下优先保留范围、预算单位、首条建议和返回键；80/110 列显示可用细目，中英文和两种主题都要复核。
4. **文档和发布。** 按内核诊断、工具范围、终端、回归和文档分别提交。README、文档中心、工作台、协议和 CHANGELOG 随功能更新。完整验收后才准备同一提交的 Windows MSI、Debian 安装包和便携包。

## 开发验收记录

- 内核的实际进程测试用回环 Anthropic 服务检查 `session/inspectDraftContext`：预览期间只出现启动时的模型元数据请求，事件水位和记忆审计不变；随后正式提交才进行计数和生成。草稿、工具定义和所选记忆的字节与任务归因一致。 完整请求体字节数和随后流式生成请求的 `Content-Length` 一致。
- Windows ConPTY 在 48/80/110 列验证 `/context`、中文预算和返回键；`F3` 可在有草稿时检查，切换上下文后仍保留草稿且没有请求模型。英文字面和排队续接、显式记忆选择的回归也通过。[48 列画面](workbench.md#发送前查看上下文) 由实际终端捕获重绘，验证排版；颜色仍以终端自身主题为准。

## 工具范围实测

同一工作区、模型档案、59 字节草稿与 72 字节项目指南。空历史，无记忆，无额外集成。Windows 开发版连接 `openai.compatible` 回环服务，Fliuno 配置窗口 8,192，预留 128。本地输入上限为 8,064 字节：

| 范围 | 工具数 | 预览生成正文 | 结果 |
| --- | ---: | ---: | --- |
| `all` | 19 | 12,397 B | 发送前拒绝，HTTP 0 次 |
| `project` | 7 | 7,003 B | 通过，HTTP 1 次 |
| `none` | 0 | 3,475 B | 通过，HTTP 1 次 |

```powershell
python -B scripts/measure_draft_context.py ./fliuno-app-server.exe --version 0.0.22 --window 8192 --tool-scope all --tool-scope project --tool-scope none
```

此时开发二进制尚未改版本号。回环模型的回复是固定的，结果只证明本地请求预算及序列化。发送成功的两档，预览字节与实际 HTTP 正文相同。长历史、更多检查或连续工具回执可能让请求再次超过上限。Anthropic 回环测试另验证项目范围入队重启后仍生效，并拒绝模型自行提出的范围外工具，不进入审批。

- 在 Windows ConPTY 下，全部和项目两档均通过了查找、读取、审批精确编辑和真实隔离检查（退出码 `0`）。Git 差异只涉及 `src/greeting.txt`。项目档的编辑任务每次生成都只开放 8 个工具，其中 1 个为宿主登记的检查；下一条恢复默认范围。已看过 48/80/110 列的中文预览和 110 列的英文预览。

## 验收门槛

- 用固定草稿对比 0.0.22 和候选的请求大小、输入上限、收到的计数或未发送原因。至少测短项目问答、一次工具读、一个经批准的精确编辑和检查，验证实际文件、退出码与审批记录。用真实本机模型另做至少一次小窗口尝试；模型本身不成功时分开记录。
- 预览不创建任务或事件，不走供应商/Embedding 请求。覆盖默认、断线、换模型、项目指南变化、权限撤销、空历史和长工具回执。涵盖四种模型接口的投影合同；真实供应商覆盖和模拟覆盖分开记录。
- Windows 和 Debian 完整 CI，安装、升级、卸载和重装。真实终端截图覆盖 48/80/110 列，检查中英文宽度、对齐、换行、焦点和键位。用同一构建目录并检查 C/D/E 余量，安装及升级证据留在缓存之外。
