# 0.0.10 · 终端协作工作流

[开发路线图](roadmap.md) · [终端工作台指南](workbench.md) · [0.0.9 发布验收](execution-evidence.md#009-发布验收2026-11-27)

0.0.9 让用户能在多个会话间发现和处理工作。0.0.10 将扩展从编写任务、安排后续工作、审阅计划，到恢复会话和检视结果的完整流程。每条工作流同时交付内核行为、协议入口、终端操作和故障验收。

## 参考实现

- Codex 本地源码 `a1604a8` 的 `codex-rs/tui/src/slash_command.rs` 定义了 Plan 和 Fork 入口。`bottom_pane/pending_input_preview.rs` 将排队消息与正在等待的用户问题分别显示。[Codex CLI 命令](https://learn.chatgpt.com/docs/developer-commands?surface=cli)
- Claude Code 本地仓库 `2771d55` 的交互指南入口和变更记录覆盖提示排队、分支、计划和回退。队列与回退的修复记录表明，等待中的提示、已执行的任务和文件副作用需要各自的恢复语义。[Claude Code 交互模式](https://code.claude.com/docs/en/interactive-mode)
- OpenCode 本地源码 `d284e7c` 用作终端组件与快捷键设计的补充参考。Fliuno 沿用自己的工作区、会话、任务和审批布局。

## 交付与验收

| 用户工作流 | Rust 内核与协议 | 终端工作台 | 验收重点 |
| --- | --- | --- | --- |
| 计划与实施 | 创建冻结的计划任务，约束工具清单和执行入口。保存计划修订与澄清。实施使用新的任务回执与权限判断。 | 草稿切换计划模式，显示任务模式、最新计划与澄清。可从完成的计划发起实施草稿。 | 模型伪造写操作被拒，允许的读仍走权限。重启后保留计划和澄清，开始实施需要显式提交。 |
| 持久提示队列 | 会话范围的队列存储、顺序、幂等入队与取消。任务启动与消费记录原子提交。明确未知结果、暂停和恢复的规则。 | 草稿可入队，队列有预览、取消、启动状态和明确的恢复入口。区分补充当前任务与安排新任务。 | 多个排队项保持顺序，竞态只生成一个任务。覆盖审批期间入队、取消、强制退出和重复请求。 |
| 会话管理和分支 | 记录同工作区分支来源与固定完成水位。新任务可使用有界的历史投影。沿用会话检索、重命名及归档。 | 可搜索会话并切换归档视图。显示分支来源，可从已完成任务或当前会话创建分支。 | 分支冻结来源历史。审批、运行中任务、授权、队列项以及附件执行权限按原作用域校验。 |
| 任务与工具时间线 | 带水位和游标的结构化任务详情。提供任务决策、工具、产物和预算的有界读取，复用现有回放与上下文归因。 | 可切换任务摘要、对话、事件与交付物视图，从工具事件追到审批或结果。 | 大事件只在需要时展开。窄窗口可读，重连不跳过事件，错误与未知结果可区分。 |
| 操作命令和输入 | 用共享的客户端请求封装统一操作及状态反馈。按需获取服务能力、模型与预算状态。 | 在 Fliuno 现有布局增加从草稿出发的命令入口与快捷键提示。运行期间可查看状态、提交澄清和处理后续任务。 | 老服务兼容性、组合字符和粘贴、键盘冲突、不同终端尺寸及状态持久性。 |
| 验收与发布 | 迁移、回放、故障注入、格式、Clippy、Schema、全工作区回归和离线演示。 | Windows ConPTY 和 Debian PTY 运行同一套关键任务，复验解包后的 x64 发布程序。 | 与历次发布的可用工作流和覆盖面核对，记录实际完成范围。校验发布包 SHA-256。 |

实现沿用工作区、会话和任务身份。计划模式和实施草稿使用不同的任务 ID。每个会话有独立的待执行队列。分支将最新 64 条会话历史的完成序列写入 SQLite，读取时复用现有对话投影。时间线和上下文归因共用原任务与事件数据。[操作指南](workbench.md) · [协议索引](protocol.md#终端协作接口)
