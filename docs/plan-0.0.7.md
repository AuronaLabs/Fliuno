# 0.0.7 · Fliuno 终端工作台

[文档中心](README.md) · [路线图](roadmap.md) · [0.0.6 验收](plan-0.0.6.md)

调研与规划：2026-11-22。Fliuno 的产品入口改为可直接使用的终端工作台，内部复用 Rust、SQLite 和现有协议。首版面向 Windows 和 Linux。

## 交付范围与验收

| 环节 | 交付与验收 |
| --- | --- |
| 安装与启动 | `fliuno --demo` 不需密钥，通过真实本机服务演示任务、审批与交付。正常启动复用模型环境变量。可指定工作区、数据库、服务程序及服务配置。帮助与版本无需 TTY；非 TTY 拒绝启动。 |
| 组织工作 | 从路径打开或切换已登记工作区；创建、选择、翻页读取会话。重开可接回已有任务。任务支持中英文与多行粘贴。 |
| 任务协作 | 任务列表与详情显示状态、计划及待办；可追加指令、回答澄清、取消。审批必须展示原操作及参数，显式允许一次或拒绝，并保持绑定到原审批。 |
| 断开与恢复 | 工作台从持久快照读取同一水位的任务和待办。长事件流按持久水位补读；连接断开后可重连，保留输入草稿。任务重试走恢复协议，未知结果明确显示且不自动重发。 |
| 交付审查 | 读取交付物目录、文本预览、修订来源和二进制元数据。下载到用户明确给出的本机路径，校验摘要，避免覆盖已有文件。 |
| 产品发布 | README 和仓库介绍改为本机 AI 工作台。GitHub Release 提供 Windows x64 和 Linux x64 自带 app-server 的压缩包与校验和，说明模型配置和快捷键。 |

## 技术取舍

- 新增 `fliuno-tui` 与 `fliuno`，采用 Ratatui 0.29 和 Crossterm 0.28，保持 Rust 1.89 基线。宽屏显示任务队列和详情，窄屏切换单列。工具与外部内容只作为展示数据，过滤终端控制字符。正常退出、启动失败或 panic 后恢复终端。
- `fliuno-client` 的 stdio 链路由后台 worker 持有。输入与渲染不等待 RPC；命令和结果有界，按当前工作区、会话、任务校验响应归属。退出同时关闭此工作台启动的服务，持久状态从数据库接回。
- 用 `work/subscribe` 建立起始快照。以短周期读取方式追赶持久水位并修复通知缺口。任务提交带幂等请求键，未获回执的审批和答复不自动重发。应用协议仍为 0.1，SQLite 不新增迁移。
- GUI、原生 macOS 沙箱、独立服务托管、模型登录管理、Run 编辑器、记忆和备份面板另行排期。外部 Agent 配置继续使用宿主配置。

## 发布检查

1. 在 Windows 和可用 Linux 环境验证离线流程：开工作区 → 建会话 → 提交 → 审批 → 预览与下载 → 退出重开后复读。验证拒绝、取消、过期审批和未知结果。
2. 验证非 TTY、窄屏、中文宽字符、多行粘贴、尺寸变化、慢 RPC 和正常或异常退出后终端状态。核对出包二进制实际可启动。
3. 通过全工作区回归、严格 Clippy 和协议 Schema 一致性检查；记录操作系统实际覆盖。验证 GitHub 描述、标签、正式发布与资产校验和。

## 调研依据

- [OpenCode TUI](https://opencode.ai/docs/tui/) 与[源代码和测试](https://github.com/anomalyco/opencode/tree/5310e42203af41c3452ee44b24fc7d0c52aaa3cc/packages/tui)：在本机浅克隆 `5310e42`，检查会话重新同步、粘贴测试和工具审批详情。保留明确的操作上下文，首版审批只提供本次选择。
- [Claude Code 交互模式](https://code.claude.com/docs/en/interactive-mode)：以会话恢复、提交与权限为基础，Fliuno 将澄清、任务状态和产物目录放在同一工作流。
- [Ratatui 终端恢复](https://ratatui.rs/recipes/apps/panic-hooks/) 与[测试](https://ratatui.rs/recipes/testing/)：在真实终端验证恢复，用缓冲后端覆盖尺寸和文字布局。[Ratatui 0.29.0](https://crates.io/crates/ratatui/0.29.0) · [Crossterm 0.28.1](https://crates.io/crates/crossterm/0.28.1)
