# 注册身份与持久授权

[文档中心](README.md) › [本机执行与隔离](README.md#本机执行与隔离) · [沙箱](sandbox.md) · [应用协议](protocol.md)

工具名称和 Agent ID 用于选择注册项。持久审批和排队任务另存注册摘要，执行前必须匹配当前注册；同名不会把旧授权转移到新配置。应用协议 `initialize.capabilities.registrationAuthority:true` 表示支持这项检查。

## 工具组注册

宿主通过 `Kernel::register_tools(Vec<Box<dyn Tool>>)` 注册完整工具组。core/registry 先暂存并校验所有名称、摘要、组内重复及与现有注册的冲突，再一次合并；任何项非法时，原有注册完整保留，暂存与未处理的工具对象一起释放。空列表不改变注册表，单项 `register_tool` 也复用同一入口。名称须为 1..64 ASCII 字母、数字、下划线或连字符，摘要须为 64 位小写十六进制。

工作区、Skills、MCP、exec 和终端适配器都通过该入口提交。失败不会留下前面已经添加的部分工具，也不能替换现有工具或影响其待批调用；成功注册仍不执行工具，每次调用继续走独立策略和审批。自定义工具必须提供不可变的公开契约与注册身份。

这是内存注册表的整组提交，不是适配器初始化或远端 IO 的事务。MCP 可能已经握手和发现工具，exec 可能已读取程序摘要，终端可能已准备状态目录；失败只保证不发布部分注册，并释放本次暂存对象。既有进程、远端副作用、跨适配器启动及宿主文件准备不由该 API 撤销。它不增加 RPC 方法或数据库字段。

## 绑定与执行

创建工具审批时，内核把 `Tool::authority()` 保存到 `Approval.authority`。允许一次时先核验摘要，再检查当前策略，随后才提交执行身份并交给 worker。注册项缺失、摘要变化或旧记录没有摘要时，任务持久失败，不产生 `tool_started` 或工具 IO。拒绝审批始终可以进行。

创建外部 Agent 任务时，把 `AgentBackend::authority()` 保存到 `Task.backendAuthority`。准备启动时再次匹配，注册缺失或绑定不符会持久化失败状态与 `task_failed` 事件，不创建 Agent run，避免任务一直显示运行中。相同 `clientRequestId` 仍返回原任务及原摘要，不会刷新绑定。要使用新配置，需要创建新任务；给原请求重复提交不构成重新授权。

已发出的外部操作继续遵循未知结果边界：摘要匹配不能证明副作用未发生，不能用于自动重发。已启动 ACP 进程的权限在重启后失效，A2A 的远端运行记录也不会因此自动续执行。

## 内置适配器

| 注册 | 摘要输入 |
| --- | --- |
| MCP stdio host | 全部配置、实际传递的环境值、原生 executable 内容 SHA-256 |
| MCP Streamable HTTP host | 全部配置、已解析的凭据请求头字节 |
| MCP 工具 | host 摘要、远端名称、描述、输入 Schema |
| MCP 资源/提示工具 | host 摘要、固定方法、名称、描述、效果类型和输入 Schema |
| ACP Agent | 全部配置、实际传递的环境值、原生 executable 内容 SHA-256 |
| A2A Agent | 全部配置、实际 bearer token |
| Skills 工具 | 规范化宿主目录路径、发现时元数据、公开工具契约 |

配置包括参数、隔离、伴随文件清单、环境名称、资源与超时预算等对应字段。环境和 HTTP 凭据在注册时解析并保存在适配器内存中，传输使用同一份冻结值；Windows 启动所需的 `SystemRoot` 也纳入进程配置的解析结果，缺失或非 Unicode 时拒绝注册。隔离层仍按固定策略生成私有 scratch 路径，并覆盖保留的临时目录变量。运行中修改宿主环境不更新既有注册，需重建注册后新建任务。

带伴随文件的 MCP 展示别名仍包含清单摘要，空清单保留原别名。无论别名是否变化，持久授权都检查完整摘要。exec 和 terminal 的现有配置身份继续包含在其工具名中，由默认工具契约摘要一并绑定。

MCP 工具结果显式拒绝不完整结果，即使 SDK 已将带部分内容的响应解码为普通结果。未声明 Tasks 扩展的远端继续使用 `mcp.tool.v2` 摘要域；启用 Tasks 后使用 `mcp.tool.v3`，额外绑定对端 Tasks 能力，避免旧授权允许新的远端任务句柄行为。Tasks 控制工具使用 `mcp.task.v1`，绑定主机注册摘要、扩展设置和具体方法。上述变更不增加数据库结构。注册绑定由 v8 引入，v9 增加[显式上下文选择](context.md)，不重写旧授权。

Skills 保留每个已发现技能的独立目录能力，资源只能相对该技能读取；换宿主目录来源会使旧审批失效。它不固定资源内容，获批读取返回当前内容及摘要；完整路径、预算和脚本边界见[Skills](skills.md)。

MCP 资源和提示按握手能力注册；审批保存具体 URI/提示名称/参数以及工具摘要。端点变更不能承接旧审批，返回的资源内容或提示正文并未在注册时固定，也不变成额外权限。分页、缓存与角色数据边界见[内容通道](mcp-content.md)。

`fliuno-sandbox::LaunchSpec.program_sha256` 可固定原生程序内容。exec、隔离 MCP 和 ACP 使用注册时计算的值；暂存程序时核验实际复制字节，失败不会启动 workload。`assets` 自带的必填 pin 同样在复制时核验。`trusted_host` 通过外部 OS 路径运行，不能保证外部进程并发替换 executable 时的原子 pin；MCP 服务也在注册时初始化，注册摘要不会把初始化本身变成逐次审批操作。

## 摘要格式与自定义实现

`fliuno-core::authority_digest(domain, value)` 使用 SHA-256，固定格式域为 `fliuno.registration.v1`；另加调用方域，递归区分 JSON 类型并编码长度，对象键排序，数组顺序保留。所有注册摘要必须为 64 位小写十六进制。

默认 `Tool::authority()` 只绑定公开名称、描述、效果类型和输入 Schema；默认 `AgentBackend::authority()` 只绑定公开 `AgentSpec`。自定义适配器若有私有端点、凭据或其他行为配置，必须覆盖该方法，把实际使用的不可变配置纳入摘要。实现语义变化但配置不变时，应更新摘要域的版本。内核无法自动识别任意 trait 实现内部的配置变化。

数据库和事件仅增加摘要，不保存用于计算它的完整注册配置或凭据；模型/远端响应原有的内容仍受原通道的存储规则约束。摘要提供一致性绑定，不提供加密、签名或凭据保密：能读取摘要并猜测配置的人可能离线比对低熵输入。远端在相同端点、配置与 Schema 下自行更换代码，也不能由本地摘要认证。

## 数据库 v8

v8 在 JSON 快照增加可选的 `Approval.authority` 与 `Task.backendAuthority`，升级数据库版本以阻止旧内核忽略这些检查。旧记录仍能读取和查询；不补造历史摘要。旧待批工具可以拒绝，但不能再允许执行；旧排队 Agent 缺少绑定时不能启动。需要新配置授权的工作应新建任务。

测试覆盖真实 SQLite 重启、同名不同 Schema、同别名不同 HTTP 端点、空清单 stdio 参数变化、凭据与环境变化、ACP/A2A 配置变化，以及旧版本无摘要的恢复边界。平台运行证据另见 [执行验收](execution-evidence.md)。
